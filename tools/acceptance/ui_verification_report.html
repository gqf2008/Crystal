5. 发现并已修复的缺陷

5.1 NPC 对话文本区全黑（PR #2952，已合并并实机复验）

  1. 现象：铁匠对话窗能开、服务端已下发（日志 🧙 NPC 对话: 1 行），文本区全黑。修复前文本区像素：主色 (14,12,11) 占 98.5%，全区域仅 162 种颜色（纯底板）。
  2. 根因：npc_ui_system 行渲染查询以 With<NpcDialogWidget> 过滤，而 8 个行实体在 f6bbef83（bevy_ui 迁移）丢了该标记 → 查询恒空 → 文字永不写入。窗口显隐走面板根，故「能开但无字」。
  3. 修复：行实体 spawn 补标记（1 行结构性修复）+ 回归测试 npc_line_entities_carry_dialog_widget_marker（红检：去掉标记 FAILED；绿检：恢复通过）。
  4. 审查：独立审查通过——根因链经 git 历史证实，全部同类实体（滚动条/关闭钮/任务钮/叠加标签）的标记-查询对应关系逐一核对无误命中。
  5. 实机复验：同流程重跑，文本区 532 种颜色（+370 = 文字字形像素），截图可见「Merchant_Smith: 你想说什么？」。

8. 过程纠偏记录（本次踩坑）

  1. nearby RPC 返回字段是 entities 不是 npcs——脚本首轮误读字段报「找不到铁匠」。
  2. npc_call 的 key 必须与服务端脚本节名大小写一致（[@MAIN]），不匹配则服务端静默忽略。
  3. chat RPC 参数名是 message 不是 text——参数错时返回 missing message，@move 根本没发出去。
  4. 服务端 CallNPC 有曼哈顿距离 ≤2 校验（npc.rs）——必须 @move 到相邻格再呼叫。
  5. 客户端 Start-Process 启动必须带 D:\toolchains\msys64\ucrt64\bin 进 PATH，缺运行时 DLL 进程秒退且无日志（与火绒拦截表象相同，注意区分）。
