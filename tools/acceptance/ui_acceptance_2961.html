逐项证据

项 1 · 坐骑遮挡半透明 #2965

根因：attach_mount_layer 只挂 SpriteLayer，未像 attach_player_layers 那样同挂 GhostLayer，遮挡系统查询不到残影层 → 走到建筑 / 树后被整个剔除。审查又抓出 MountUpdated 下马主路径的 ghost 泄漏，一并修。

实机复验（本轮补齐）：@make LeatherBridle 1 + @make Saddle 1 → @ride（客户端日志 client_bevy::actor::spawn：玩家 24495 骑乘坐骑 type=0）→ 骑乘走过树冠 → 骑手与虎体以半透明残影压在树叶之上，不再消失。

项 2 · 聊天窗可拖 #2966

根因：曾把 C# MainDialogs.cs:697 的 Movable = true 误读成整窗可拖 —— 实际那是滚动滑块 PositionBar。修法：移除整窗拖动，并补上 WindowDragState::unregister 契约（窗口隐藏时必须注销，否则残留矩形变成死点击区）。

实机复验：面板内拖动玩家不移动；面板左边框锚定区像素原位；正控制（面板外世界点）仍可走。

项 3 · IME 候选乱码 #2967 · #2971 · #2973

三层根因逐层修：

  1. 候选条标签用 Arial + parley 的 Han 脚本回退，而该回退只在首次排版生效 → 候选全豆腐（修 #2967）。
  2. 聊天面板同样豆腐：chat.rs 是最后一个把 Arial 当中文正文主字体的模块（grep load_ui_font 仍有约 50 处调用，多为纯拉丁 / 单次排版站点），输入框 > □□、聊天记录 [玩家]: □□，连登录欢迎语整块都是 □（修 #2971）。
  3. Enter 开框当帧把回车符写进草稿（opened_trigger 漏登记 Enter 路径），光标因此多算一位（修 #2973）。

实机判据（全部取自 RPC 真值）：ime_composing == "nihao"、chat_input_text == "你好"、中文输入过程中 chat_input_text 恒为空（无裸 ASCII 泄漏）。

项 4 · 商城内容错位 #2968 · #2970

根因：按 C# GameshopDialog 重写布局（面板 Title[749] 696×476 @(164,146)、8 格 125×146 @(152+i%4×132, 115/275)、分类栏原点 (120,117)）。

过程中实机复验立刻抓到 P0：game_shop_ui_system 把 9 个 &mut Text 查询拆成两个 ParamSet —— Bevy 的冲突豁免只在单个 ParamSet 内部生效，两个并集在系统元数据上相撞，一进游戏就 panic 退出（exit 101）。修 #2970（合并为单个 8 项 ParamSet）+ 回归测试。

实机判据：C# 坐标 4 个点全部命中 root=GameShop。

项 5 · 滚动条缺失 #2968

根因：UiScrollList 的屏幕原点只按根实体算，子列表错位；隐藏列表仍会吞滚轮；商城分类条与行会双列表未绑轨道。修法：原点沿 ChildOf 链逐级累加、隐藏列表加可见性闸门、各自绑定轨道。

实机判据：截图 —— 商城分类条渲染出滑块（约 1/5 行程）与上下箭头；行会 Members / Storage 两条轨道并排。

项 6 · 拖拽穿透 #2966

根因：常驻窗口（药水腰带等）不是 DialogManager 对话框，世界点击闸门看不到它们；且隐藏后不注销会留下陈旧矩形。修法：WindowDragState::over_window 作为世界点击闸门 + 隐藏必须 unregister（审查 P1）。

实机判据：拖腰带不移动玩家；点拖后腰带落点不穿透；正控制空白世界点仍可走。

残余缺口

  1. 已处理：ServerRust CI 三层红（fmt → clippy → 测试栈溢出）已修（#2977），并把 fmt/clippy 补进 AGENTS.md 门禁防复发。
  2. 已处理：ui_alignment 的常量断言已拆出 require_assets!（#2979），CI 无 Data/ 时也真跑。
  3. 背包扩容钮 z=8（全仓实测：17 处 z=10、npc.rs 一处 z=9、仅背包 z=8）—— 把 z 提到 10 才是结构性正解。
  4. mail.rs / npc.rs / npc_goods.rs 的列表滚轮仍为 step: 3，而 C# 对应处是 1 行/格。
  5. 商城仍缺物品图标、职业分区页签、Preview/Viewer 视图、qty_up 的 StackSize 上限（服务端会静默丢弃超量）；排行榜滚动为文档化的 no-op。
  6. new_char_ui_system 是唯一剩下的「同函数双 ParamSet」，当前字段不重叠但无初始化级测试。
  7. Enter 分支不判 key.repeat，长按回车会反复开 / 关输入框（既有行为）。
  8. 同类站点已逐个核实：不构成风险。通知条 chat_notice.rs:73 虽是「先建空串、后写内容」的 Arial 文本，但 ChatNoticeState 全仓无写入方（不可达）；guild.rs 的 Arial 文本是 ▲/▼ 符号；hud.rs 传 Arial 的是经验/等级/金币数字标签。
  9. 项 5 的实机证据是截图人工复核（脚本只截图，无滚动行为断言）。
  10. 坐骑装备那一步目前没有 RPC 原语（需界面操作），本轮先用界面把坐骑装好再骑乘验证遮挡。

复现方法

# 0) 客户端依赖 msys64/ucrt64 与 libpinyin 的 DLL，缺任一目录会以 0xC0000135 静默退出
$env:PATH = 'D:\toolchains\msys64\ucrt64\bin;D:\toolchains\libpinyin-install\bin;' + $env:PATH
$env:LIBPINYIN_DIR = 'D:/toolchains/libpinyin-install'

# 1) 服务端（后台常驻）
cd ServerRust; ./target/release/mir2_server.exe

# 2) 三项实机复验（脚本各自起停客户端）
powershell -File tools/acceptance/ui_bugfix_verify.ps1    # 项 2/4/5/6  -> 16/16
powershell -File tools/acceptance/ime_rpc_verify.ps1      # 项 3        -> 10/10（需先起客户端）
powershell -File tools/acceptance/ui_interact_sweep.ps1   # 40 窗回归   -> 41/41

实机脚本有两个已踩过的陷阱（脚本内已注释）：正控制点必须落在可走瓦片（改用 4 方向 8 点探测，任一可走即证通路）；像素锚定必须避开动态内容（聊天行实时刷新、输入光标 2Hz 闪烁、输入行随焦点变色），故项 2 改用面板左边框静态条，并先自检两帧稳定性。
