# 运营就绪 · 外部资源交接清单（2026-09-23）

**给人工的一句话**：本机能把「单机口径」的运营就绪做到可跑、可复现、有判据——七项工具
（部署/回滚/压测/可观测性/容量/故障注入/告警）+ 六步性能改动，世界侧安全线 **≥120 会话全绿零丢包**、
登录 200 并发真延迟 p95 **0.86s**。但**「可交付上线运营」仍不成立**，卡点全在下表五项
——它们**本机拿不到真证据**，需要外部资源或人工决策，故列成交接清单（每项都写清判据、已完成到哪、缺什么）。

> 上游文档：`tools/ops/CAPACITY.md`（含 §7 同源清单）、`tools/ops/README.md`（四项工具判据手册）。
> walgit 线程：`crystal-ops-readiness`（每条改动都有 patch/review/merge_result 与实测数据）。

## 1. 独立压测机 + 生产拓扑

| | |
|---|---|
| **判据** | 在**与服务器不同机**的压测机上，用 `tools/ops/bot.py` 复现并发阶梯，产出：并发成功率、登录真延迟 p50/p95、服务端 tick 心跳滞后（`heartbeat:` 行的 `interval_ms/lag_pct`）、RSS/CPU 曲线、`gate mailbox full` 与 `send buffer full` 计数；并与本机基线（≥120 会话零丢包）对账 |
| **本机已做到** | 协议级机器人 + 阶梯脚本 + 信号分离计数（单目标丢弃 / 广播延迟投递 / 发件箱满）+ 账号播种工具，一条命令可跑；判据脚本 `capacity_ramp.ps1` 已入库 |
| **缺什么** | 一台独立的压测机（建议同规格×1 + 网络隔离）、**生产拓扑**（网关/世界/DB 是否分机、是否走 LB）、服务器规格基线 |
| **为什么本机不行** | 压测机与服务端同机争 CPU/内存/磁盘：20 会话时压测机自身占用已显著影响服务端；120 会话已接近本机极限，再往上测的是压测机而不是服务端 |
| **交接产物** | 一份 `capacity_ramp.json` + 服务器侧 `health.json`，标注拓扑图与规格 |

## 2. 真实渲染客户端容量

| | |
|---|---|
| **判据** | 用**真实 Bevy 客户端**（非协议级机器人）跑同一场景，记录：帧率分布、客户端 RSS/显存、进图耗时、以及同屏 20/50 人时的渲染与网络开销；与服务端侧指标对账，确认瓶颈不在客户端 |
| **本机已做到** | 客户端可 `--real-net --auto-enter` 起并进图；`state`/`bag_probe`/`mail_probe` 等只读探针可直接读客户端真值 |
| **缺什么** | 具备稳定显卡与多实例能力的环境（本机单实例、且与服务端/压测争资源）；若要 N 个真实客户端，需要 N 台或一台具备多会话能力的机器 |
| **为什么本机不行** | 协议级机器人**不渲染**，测不到帧率/显存/输入延迟；这是两个完全不同的资源画像 |
| **交接产物** | 客户端侧帧率与资源曲线 + 与服务端 tick 的对账结论 |

## 3. ≥24h 长稳 / 老化

| **判据** | 连续运行 ≥24h（建议 72h）：① 服务端进程不重启、不 OOM；② tick 心跳 `lag_pct` 无单调上升；③ RSS 曲线无持续增长（本机实测 10~20 会话约 +7.5MB/会话，需确认长时间是否回收）；④ 零 `ERROR`（良性断连除外）；⑤ 会话可正常进出 |
| **本机已做到** | INFO 级心跳（`heartbeat: tick/online/monsters/interval_ms/lag_pct`）+ `health_report.ps1` 可把日志折成判定；本轮最长窗口 70s |
| **缺什么** | 一台可长期占用的机器 + 监控采样（本机被开发/压测反复重启，长稳窗口无法保持） |
| **交接产物** | 24h/72h 的 `health.json` 时间序列 + 结论（有无泄漏、有无滞后漂移） |

## 4. 告警通道与值班流程

| | |
|---|---|
| **判据** | ① `alert_probe.ps1` 的告警（tick 抖动 / 真错误 / 慢读者被踢 / 邮箱背压 / RSS）能真的**送达人**（IM/邮件/电话任一）；② 有值班表与升级路径（谁在多长时间内响应）；③ 做一次演练：人为制造阈值越界 → 有人收到并及时处理 |

| **交接产物** | 通道配置 + 一次演练记录（时间线：越界 → 通知 → 响应） |

## 附：本机仍可做、但本轮未做的两项（不是外部依赖，只是排期）

| 项 | 判据 | 现状 |
|---|---|---|
| **7.5MB/会话内存拆解** | 定位 10/20 会话下 +7.5MB/会话的构成（地图块缓存 vs 每会话实体副本），给出可外推公式与优化项；若含缓存，确认是否有上限/淘汰 | 已测出斜率；未拆解。200 会话粗估 ≈1.5GB（单机单图） |
| **运行中存储故障降级** | 运行中把 DB 置只读 → ① 不 panic；② 登录写 `is_online`、存档、邮件落库失败的**行为明确**（吞错/告警/拒绝服务），且不产生静默数据损坏 | 只验过「只读起服不 panic」；运行中写失败未演练 |

这两项与界面打磨（P3-2 行会 NOTICE 空黑区、#782 仓库/商城物品名）一起排在本机队列；
