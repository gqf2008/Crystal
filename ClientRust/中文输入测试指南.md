## 技术说明

### winit 0.30 的文本输入机制

在 winit 0.30 中,IME 输入的文本会通过 `KeyEvent.text` 字段传递:

```rust
fn key_down_event(&mut self, ctx: &mut Context, input: KeyInput, _repeated: bool) -> GameResult {
    if let Some(text) = &input.event.text {
        for ch in text.chars() {
            // 这里会接收到中文字符 '你', '好' 等
            scene_manager.handle_text_input(ch);
        }
    }
    Ok(())
}
```

### IME 工作原理

1. **输入拼音阶段** (如 "ni", "hao"):
   - 这些字母可能出现在 `KeyEvent.text` 中
   - 也可能通过 `WindowEvent::Ime::Preedit` 发送 (ggez 0.10 不支持)

2. **选择候选词** (选择 "你好"):
   - winit 发送 `WindowEvent::Ime::Commit("你好")`
   - **同时** `KeyEvent.text` 也会包含 "你好"
   - 我们的实现使用 `KeyEvent.text` 接收

3. **文本传递流程**:
   ```
   IME 输入 → winit KeyEvent.text → key_down_event →
   scene_manager.handle_text_input → LoginDialog.handle_text_input →
   TextBox.handle_char_input → 显示在屏幕上
   ```

## 已知限制

### ggez 0.10 的 IME 限制
- ✅ 支持: `KeyEvent.text` 字段 (包含最终确认的中文字符)
- ❌ 不支持: `WindowEvent::Ime::Preedit` (拼音编辑预览)
- ❌ 不支持: `WindowEvent::Ime::Commit` 事件直接处理

**影响**:
- ✅ 能正常输入中文
- ❌ 无法显示拼音编辑预览 (输入过程中的 "ni hao" 不会在输入框显示)
- ✅ 确认后的中文会正常显示

### 为什么不使用自定义事件循环?

最初尝试了自定义 `event_loop.run()` 来拦截 `WindowEvent::Ime` 事件,但遇到问题:
- 需要手动调用 ggez 的所有内部状态更新函数
- ggez 0.10 的 API 不稳定 (有些函数参数数量不明确)
- 容易导致渲染问题 (白屏、事件丢失等)

**当前方案更稳定**:
- 使用 ggez 标准的 `event::run()`
- 利用 `KeyEvent.text` 获取 IME 结果
- 虽然没有拼音预览,但中文输入功能完整

## 故障排除

### 问题 1: 中文字符无法输入
**检查**:
1. 确认 IME 已正确切换 (屏幕右下角应显示中文输入法图标)
2. 查看日志是否有 "Text input: '你'" 等消息
3. 确认输入框已获得焦点 (点击输入框)

### 问题 2: 中文显示为方块
**原因**: 字体未正确加载
**检查**:
- 日志中应有 "✓ 中文字体加载成功: AlibabaPuHuiTi"
- 检查字体文件是否存在: `src/resources/fonts/AlibabaPuHuiTi-3-55-Regular.ttf`

### 问题 3: 拼音不显示
**这是正常的!** 当前实现不支持拼音编辑预览,只会显示最终确认的中文。
