# 游戏场景加载流程全面审查报告

## 📋 执行总结

通过对当前代码的深入分析,发现游戏在**场景切换、地图加载、人物初始化**方面存在以下关键问题和优化点:

### 🔴 严重问题
1. **Canvas 残留问题未完全解决** - SelectScene 背景仍可能残留
2. **地图/玩家信息到达顺序不确定** - 可能导致摄像机位置错误
3. **缺少加载状态提示** - 用户不知道是否正在加载

### 🟡 性能问题
1. **缺少纹理预加载** - GameScene 首次绘制可能卡顿
2. **没有资源复用** - 每次切换场景都重新创建对象
3. **同步加载地图** - 大地图加载会阻塞主线程

### 🟢 架构优点
1. **事件驱动架构良好** - 网络事件处理清晰
2. **场景管理器设计合理** - 支持延迟切换
3. **摄像机系统完善** - 边界限制正确

## 🔍 详细分析

### 1. 场景切换流程

#### 当前流程
```
LoginScene (输入账号密码)
    ↓ [发送登录请求]
    ↓ [收到 LoginSuccess 事件]
    ↓ [设置 ready_for_character_select = true]
    ↓ [program.rs::check_login_to_select_transition() 检测]
    ↓ [预加载 SelectScene 纹理]
    ↓ [创建 SelectScene + 初始化]
    ↓ [替换当前场景]
    ↓
SelectScene (选择角色)
    ↓ [点击"开始游戏"按钮]
    ↓ [设置 pending_scene_change = Some(SceneType::Game)]
    ↓ [program.rs::check_select_to_game_transition() 检测]
    ↓ [切换到 GameScene]
    ↓ [如果有缓存的 MapInformation,立即发送]
    ↓
GameScene (游戏主场景)
    ↓ [收到 MapInformation 事件]
    ↓ [同步加载地图文件 (.map)]
    ↓ [收到 UserInformation 事件]
    ↓ [创建玩家对象]
    ↓ [更新摄像机位置]
    ↓ [开始渲染]
```

#### 🔴 问题 1: Canvas 残留

**现象**: SelectScene 的背景图像 (Prguse_65) 残留在 GameScene 左下角

**根本原因**:
- `Canvas::from_frame(ctx, bg_color)` 只设置背景色,不清空已绘制内容
- 之前场景的纹理仍在帧缓冲中

**当前修复**:
```rust
// GameScene::draw() 开头
let clear_rect = Rect::new(-100.0, -100.0, screen_width + 200.0, screen_height + 200.0);
canvas.draw(&clear_mesh, DrawParam::default());
```

**问题**: 
- 矩形可能不够大
- 每帧都绘制黑色矩形浪费性能
- 没有考虑 Canvas 的坐标系统变化

**建议修复**:
```rust
// 方案1: 在 program.rs 中每次创建新 Canvas 前清空旧的
canvas.finish(ctx)?;  // 完成旧 Canvas
ctx.gfx.clear(...);   // 清空帧缓冲

// 方案2: 使用 ggez 的 clear() 方法
canvas.set_sampler(FilterMode::Nearest);
// 在 GameScene 第一次绘制时标记已清空
```

#### 🔴 问题 2: 地图/玩家信息顺序不确定

**场景**: 服务器可能先发送 `UserInformation`,后发送 `MapInformation`

**当前处理**:
```rust
// UserInformation 到达时
if map_width_px > 0.0 && map_height_px > 0.0 {
    // 地图已加载
    self.camera.follow_target_clamped(...);
} else {
    // 地图未加载
    self.camera.follow_target(...);  // 无边界限制!
}

// MapInformation 到达时
if let Some(ref user) = self.user {
    // 玩家已存在,更新摄像机
    self.camera.follow_target_clamped(...);
}
```

**问题**:
- 如果 UserInfo 先到达,摄像机可能设置在 (0,0) 附近
- 如果 MapInfo 后到达,需要重新计算摄像机位置
- 中间的几帧可能显示错误的视角

**建议优化**:
```rust
// 状态机模式
enum GameSceneState {
    WaitingForData,           // 等待地图和玩家数据
    LoadingMap,               // 加载地图中
    Ready,                    // 就绪,可以渲染
}

// 只有当 map + player 都准备好时才开始渲染
if self.map_renderer.width > 0 && self.user.is_some() {
    self.state = GameSceneState::Ready;
}
```

#### 🟡 问题 3: 缺少加载状态提示

**现象**: 从 SelectScene 切换到 GameScene 后,屏幕可能是黑的或显示残留图像

**用户体验**: 用户不知道是否正在加载,可能以为程序卡死

```rust
enum LoadingState {

// draw() 方法中
match self.loading_state {
    LoadingState::LoadingMap(ref name) => {
        // 绘制 "正在加载地图: XXX" + 进度条

    }
    LoadingState::WaitingForPlayer => {
        // 绘制 "等待角色数据..." + 旋转图标

        // 正常渲染游戏
    }
}
```

### 2. 地图加载流程

#### 当前实现
```rust
fn load_map_file(file_name: &str, screen_width: f32, screen_height: f32) 
    -> Result<MapRenderer> 
{
    let map_path = format!("Map/{}", file_name);
    let mut reader = MapReader::new();
    reader.load_from_file(&map_path)?;  // ⚠️ 同步阻塞!
    
    Ok(MapRenderer {
        cells: reader.map_cells,
        width: reader.width,
        height: reader.height,
        // ...
    })
}
```

**🔴 严重问题: 同步阻塞主线程**

大型地图 (200x200 以上) 加载可能需要 100-500ms,会导致:
- 游戏卡顿/冻结
- 用户体验差
- FPS 下降到 0

**建议优化: 异步加载**
```rust
// 方案1: 使用 tokio 异步加载
pub async fn load_map_async(file_name: String) -> Result<MapData> {
    tokio::task::spawn_blocking(move || {
        let mut reader = MapReader::new();
        reader.load_from_file(&format!("Map/{}", file_name))?;
        Ok(reader.into_map_data())
    }).await?
}

// 方案2: 使用消息队列
pub struct MapLoader {
    tx: mpsc::Sender<MapLoadRequest>,
    rx: mpsc::Receiver<MapLoadResult>,
}

impl MapLoader {
    fn request_load(&self, file_name: String) {
        self.tx.send(MapLoadRequest { file_name }).ok();
    }
    
    fn check_loaded(&mut self) -> Option<MapLoadResult> {
        self.rx.try_recv().ok()
    }
}

// GameScene 使用
fn process_event(&mut self, event: &GameEvent) {
    match event {
        GameEvent::MapInformation { file_name, ... } => {
            self.loading_state = LoadingState::LoadingMap(title.clone());
            self.map_loader.request_load(file_name.clone());
        }
    }
}

fn update(&mut self, dt: f32) {
    if let Some(result) = self.map_loader.check_loaded() {
        match result {
            Ok(map_data) => {
                self.map_renderer = MapRenderer::from(map_data);
                self.loading_state = LoadingState::Ready;
            }
            Err(e) => {
                tracing::error!("地图加载失败: {}", e);
            }
        }
    }
}
```

**现象**: GameScene 第一次渲染时需要从 .lib 文件加载大量纹理

**问题**:
- 第一帧可能耗时 100-300ms
- 导致明显卡顿
- 纹理加载是同步的

**当前预加载**: 只有 SelectScene 有纹理预加载

**建议添加 GameScene 预加载**:

## 🔧 代码示例: 完整的 GameScene 状态机

```rust
pub enum GameSceneState {
    Initializing,                      // 刚创建,等待事件
    WaitingForMapInfo,                 // 等待地图信息
    LoadingMap(String),                // 加载地图中
    WaitingForPlayerInfo,              // 等待玩家信息
    PreloadingAssets,                  // 预加载资源
    Ready,                             // 就绪,可渲染
    Error(String),                     // 加载失败
}

impl GameScene {
    fn update(&mut self, dt: f32) {
        match &self.state {
            GameSceneState::LoadingMap(_) => {
                // 检查异步加载是否完成
                if let Some(map_data) = self.map_loader.check_result() {
                    self.map_renderer = MapRenderer::from(map_data);
                    
                    if self.user.is_some() {
                        self.state = GameSceneState::PreloadingAssets;
                    } else {
                        self.state = GameSceneState::WaitingForPlayerInfo;
                    }
                }
            }
            
            GameSceneState::PreloadingAssets => {
                // 预加载纹理 (分帧加载,避免卡顿)
                if self.preload_next_batch() {
                    self.state = GameSceneState::Ready;
                    tracing::info!("✅ GameScene 初始化完成!");
                }
            }
            
            GameSceneState::Ready => {
                // 正常游戏逻辑
                self.update_player(dt);
                self.update_camera(dt);
                self.update_objects(dt);
            }
            
            _ => {}
        }
    }
    
    fn draw(&mut self, ctx: &mut Context, canvas: &mut Canvas) {
        // 先清空画布
        self.clear_canvas(canvas);
        
        match &self.state {
            GameSceneState::LoadingMap(name) => {
                draw_loading_screen(canvas, &format!("正在加载地图: {}", name));
            }
            
            GameSceneState::WaitingForPlayerInfo => {
                draw_loading_screen(canvas, "等待角色数据...");
            }
            
            GameSceneState::PreloadingAssets => {
                let progress = self.preload_progress();
                draw_loading_screen_with_progress(canvas, "加载资源中...", progress);
            }
            
            GameSceneState::Ready => {
                // 正常渲染
                self.draw_map(ctx, canvas);
                self.draw_player(ctx, canvas);
                self.draw_ui(ctx, canvas);
            }
            
            GameSceneState::Error(msg) => {
                draw_error_screen(canvas, msg);
            }
            
            _ => {
                draw_loading_screen(canvas, "初始化中...");
            }
        }
    }
}
```

当前的架构基础良好,但在**用户体验和性能**方面还有很大提升空间。通过实施上述优化方案,可以达到:

建议按照优先级逐步实施,先解决关键问题,再进行性能优化。
