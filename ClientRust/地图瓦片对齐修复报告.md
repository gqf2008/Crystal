# 地图瓦片对齐修复报告

**修复日期**: 2025-10-08  
**问题**: 地图瓦片渲染错位,与C#原版不一致  
**影响范围**: 所有地图层 (BackImage, MiddleImage, FrontImage, TileAnimation, MiddleAnimated)

---

## 🐛 问题分析

### **症状**
- 地图瓦片位置不正确
- 对象错位
- 整体画面偏移

### **根本原因**
**draw_x** 坐标计算公式错误!

**❌ 错误实现** (Rust之前的版本):
```rust
let draw_x = (x - self.player_x + offset_x_tiles) as f32 * TILE_WIDTH 
    - offset_x_tiles as f32 + 0.0;
```

**✅ 正确实现** (C#原版):
```csharp
drawX = (x - User.Movement.X + OffSetX) * CellWidth - OffSetX + User.OffSetMove.X;
```

### **关键差异**

C#版本中 **最后的 `- OffSetX`** 是以 **格子数(tiles)** 为单位,不是像素!

假设:
- `OffSetX = 8` (tiles,屏幕宽度的一半约8个格子)
- `CellWidth = 48` (像素)

**计算示例** (玩家在 100,100,屏幕800x600):
```
正确: (100 - 100 + 8) * 48 - 8 + 0 = 8 * 48 - 8 = 384 - 8 = 376像素
错误: (100 - 100 + 8) * 48 - 8 * 48 + 0 = 8 * 48 - 384 = 0像素 (完全偏移!)
```

**这个 `-8` 像素是微调值**,用于将地图稍微向左偏移,可能是为了视觉平衡或UI对齐!

## 📐 C# 原版逻辑详解

### **坐标系统**

**1. OffSetX/OffSetY 计算**:
```csharp
OffSetX = Settings.ScreenWidth / 2 / CellWidth;     // 屏幕中心的格子偏移
OffSetY = Settings.ScreenHeight / 2 / CellHeight - 1;
```
- 800x600 屏幕: OffSetX = 800/2/48 = **8** tiles
- OffSetY = 600/2/32 - 1 = **8** tiles (减1是因为Y轴要向上偏移一格)

**2. 绘制位置计算**:
```csharp
drawX = (x - User.Movement.X + OffSetX) * CellWidth - OffSetX + User.OffSetMove.X;
drawY = (y - User.Movement.Y + OffSetY) * CellHeight + User.OffSetMove.Y;
```

**公式分解**:
1. `(x - User.Movement.X)` = 相对于玩家的格子差
2. `+ OffSetX` = 加上屏幕中心偏移 (把玩家移到屏幕中心)
3. `* CellWidth` = 转换为像素
4. `- OffSetX` = **微调偏移** (注意这里是tile数,不是像素!)
5. `+ User.OffSetMove.X` = 平滑移动补偿 (角色走路时的亚格子偏移)

**关键理解**:
- 第一个 `OffSetX` 参与乘法 → **像素计算**
- 第二个 `OffSetX` 直接减去 → **微调值** (tiles → pixels 但不乘)

## 🎯 技术要点

### **坐标转换链**
```
地图坐标 (tiles) 
   ↓
相对坐标 (tiles) = x - player_x
   ↓
屏幕中心对齐 (tiles) = relative + offset_x
   ↓
像素坐标 (pixels) = aligned * TILE_WIDTH
   ↓
微调偏移 (pixels) = pixel_coord - offset_x (注意:这里offset_x不乘!)
   ↓
平滑移动补偿 (pixels) = adjusted + smooth_move_x
   ↓
最终屏幕坐标 (pixels)
```

### **为什么有微调?**
`- OffSetX` 这个8像素的偏移可能是为了:
1. **视觉平衡**: 让玩家不在正中心,稍微偏右一点
2. **UI对齐**: 避免遮挡左侧UI (聊天框/技能栏)
3. **历史原因**: 原始Mir2客户端的设计遗留
