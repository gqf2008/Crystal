# 数据结构模块归属调查报告

## 调查的结构类型

以下是 `game_scene_v2.rs` 中临时定义的结构,需要确认其正确的模块归属:

- `QuestTracker`
- `Friend`
- `Relationship`
- `RelationshipType`
- `GuildObject`
- `Mail`
- `Rank`

## 调查结果

### ✅ 已在 mir2_shared (Shared 项目) 中定义

#### 1. **ClientFriend** (不是 `Friend`)
- **C# 定义**: `Shared/Data/ClientData.cs` line 122
- **Rust 定义**: `SharedRust/src/data/client_data.rs` line 885
- **字段**:
  ```csharp
  public int Index;
  public string Name;
  public string Memo = "";
  public bool Blocked;
  public bool Online;
  ```
- **结论**: ✅ 应使用 `mir2_shared::data::client_data::ClientFriend`

#### 2. **ClientMail** (不是 `Mail`)
- **C# 定义**: `Shared/Data/ClientData.cs` line 154
- **Rust 定义**: `SharedRust/src/data/client_data.rs` line 922
- **字段**:
  ```csharp
  public ulong MailID;
  public string SenderName;
  public string Message;
  public bool Opened, Locked, CanReply, Collected;
  public DateTime DateSent;
  public uint Gold;
  public List<UserItem> Items;
  ```
- **结论**: ✅ 应使用 `mir2_shared::data::client_data::ClientMail`

#### 3. **RankCharacterInfo** (不是 `Rank`)
- **C# 定义**: `Shared/Data/SharedData.cs` line 43
- **Rust 定义**: `SharedRust/src/data/shared_data.rs` line 92
- **字段**:
  ```csharp
  public long PlayerId;
  public string Name;
  public MirClass Class;
  public int level;
  public long Experience;
  public DateTime LastUpdated;
  ```
- **结论**: ✅ 应使用 `mir2_shared::data::shared_data::RankCharacterInfo`

### ❌ 未在 Shared 中定义 (UI 状态/客户端专有)

#### 4. **QuestTracker**
- **C# 中的使用**: `Client/MirScenes/Dialogs/QuestTrackingDialog.cs`
- **性质**: UI 对话框的**内部状态**,不是共享数据结构
- **观察**: 
  - C# 中 `QuestTrackingDialog` 维护任务追踪状态
  - 这是**客户端 UI 层**的数据,不需要与服务器通信
- **结论**: ❌ 不在 Shared,**应该定义在 controls 模块** (作为 QuestTrackingDialog 的内部状态)

#### 5. **Relationship** / **RelationshipType**
- **C# 中的使用**: `Client/MirScenes/Dialogs/RelationshipDialog.cs` line 9
- **性质**: UI 对话框,没有独立的 `Relationship` 数据结构
- **观察**:
  - C# 中 `RelationshipDialog` 是 UI 控件
  - 关系数据实际通过 `ClientFriend` + 特殊标记表示
  - 没有单独的 `Relationship` 类
- **结论**: ❌ 不存在独立的 Relationship 结构,**应该用 ClientFriend** 或在 controls 模块实现 UI 逻辑

#### 6. **GuildObject**
- **C# 服务器定义**: `Server/MirObjects/GuildObject.cs` line 7
- **C# 客户端使用**: `Client/MirScenes/Dialogs/GuildDialog.cs`
- **性质**: 服务器端对象,客户端使用 **网络包数据**
- **观察**:
  - 服务器有完整的 `GuildObject` 类
  - 客户端通过 `GuildDialog` 维护公会状态
  - 客户端不需要完整的 GuildObject,只需要网络包中的字段
- **结论**: ❌ 客户端不需要 GuildObject 类,**应该使用服务器包中的 GuildStatus/GuildMemberInfo 等数据**

## 总结

### ✅ 应该使用 mir2_shared 的结构:
1. **ClientFriend** (Shared/Data/ClientData.cs line 122)
2. **ClientMail** (Shared/Data/ClientData.cs line 154)
3. **RankCharacterInfo** (Shared/Data/SharedData.cs line 43)

### ❌ 应该删除的临时定义:
1. **Friend** → 改用 ClientFriend
2. **Mail** → 改用 ClientMail
3. **Rank** → 改用 RankCharacterInfo
4. **Relationship** / **RelationshipType** → 不需要,用 ClientFriend
5. **GuildObject** → 不需要完整对象,只存字段

### ⚠️ 保留在客户端的结构:
1. **QuestTracker** - UI 状态 (后续迁移到 controls)
2. **OutputMessage** - UI 层数据 (确实需要客户端定义)

## 架构原则验证

这次调查再次验证了正确的架构原则:

✅ **数据源单一性**:
- Shared 项目的数据结构 → mir2_shared crate
- 客户端 UI 状态 → controls 模块
- 不要重复定义已存在的结构

✅ **命名一致性**:
- C# 叫 `ClientFriend`,Rust 也应该用 `ClientFriend`
- C# 叫 `ClientMail`,Rust 也应该用 `ClientMail`
- 不要改名 (Friend/Mail)

✅ **模块职责清晰**:
- mir2_shared: 网络通信的数据结构
- controls: UI 对话框和控件
- scenes: 场景逻辑,协调各模块
