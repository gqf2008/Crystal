## 📌 当前瓶颈

### 主要障碍

1. **Runtime 集成**
   - Bevy 是同步的单线程框架
   - NetworkManager 需要 async/tokio
   - 需要创建专用线程或使用 tokio::spawn

2. **通道管理**
   - Bevy 需要持有 tx 发送命令
   - Network 需要持有 rx 接收命令
   - 需要线程安全的数据结构

3. **事件系统集成**
   - Bevy 需要监听网络事件
   - 需要线程间事件传递机制
   - 需要反序列化网络数据到 Bevy 组件

---

## 💡 解决方案概览

### 方案 1: 后台线程 + 通道 (推荐) ⭐⭐⭐
```rust
// 在 main_bevy.rs 中:
1. 创建网络命令发送通道
2. 在后台线程运行 NetworkManager
3. 用 Arc<Mutex<>> 共享网络事件
4. 在 Bevy Update 中定期检查事件

优点: 清晰、可控、性能好
缺点: 需要手动管理线程生命周期
```

### 方案 2: 使用 bevy_tokio 插件
```rust
// 第三方插件: bevy_tokio
1. 自动管理 tokio 运行时
2. 提供异步系统
3. 简化集成

优点: 自动化程度高
缺点: 增加依赖复杂度
```

### 方案 3: 同步网络客户端
```rust
// 改写 NetworkManager 为同步版本
1. 使用 blocking TCP
2. 在 Bevy Update 中同步收发

优点: 简单直接
缺点: 阻塞主线程，性能差
```

## 📝 核心代码示例

### 建立网络资源
```rust
#[derive(Resource)]
pub struct NetworkHandle {
    pub command_tx: mpsc::UnboundedSender<NetworkCommand>,
    pub event_queue: Arc<Mutex<VecDeque<GameEvent>>>,
}

// 在 main_bevy.rs 中:
app.insert_resource(NetworkHandle {
    command_tx,
    event_queue: Arc::new(Mutex::new(VecDeque::new())),
});
```

### 后台线程
```rust
std::thread::spawn(move || {
    let runtime = tokio::runtime::Runtime::new().unwrap();
    runtime.block_on(async {
        let mut manager = NetworkManager::new(settings, tx, rx);
        manager.run_loop().await;
    });
});
```
