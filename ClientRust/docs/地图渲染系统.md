## 概述

地图渲染系统负责将游戏地图数据可视化到屏幕上。系统采用**分层渲染**架构，支持静态瓦片、动画瓦片、混合模式、视口裁剪等功能。

### 主要特性

- ✅ 三层渲染架构（Back/Middle/Front）
- ✅ 静态与动画瓦片独立控制
- ✅ 多种混合模式（Normal/ADD）
- ✅ 视口裁剪优化
- ✅ 相机缩放和平移
- ✅ 碰撞层可视化
- ✅ 完整的调试工具

### 文件结构

```
src/ecs/systems/render/
├── map_system.rs          # 地图瓦片渲染（本文档核心）
├── debug_system.rs        # 调试可视化（网格/碰撞/边框）
└── mod.rs                 # 模块导出
```

## 核心概念

### 2.1 瓦片（Tile）

**定义**: 地图的最小渲染单元，每个瓦片对应一个图像资源。

**组件结构**:
```rust
pub struct MapTile {
    pub grid_x: i32,           // 网格X坐标（格子坐标）
    pub grid_y: i32,           // 网格Y坐标（格子坐标）
    pub layer: TileLayer,      // 所属层级
    pub library_index: i16,    // 图库索引（0-399）
    pub image_index: u16,      // 图像索引（库内图片编号）
    pub use_blend: bool,       // 是否使用混合模式
}
```

### 2.2 层级（Layer）

游戏地图分为三个渲染层，**自下而上绘制**：

| 层级 | 枚举值 | 用途 | 示例 |
|------|--------|------|------|
| **Back** | `TileLayer::Back` | 地面、地板 | 草地、泥土、石板 |
| **Middle** | `TileLayer::Middle` | 装饰物、墙壁 | 围栏、低矮物体 |
| **Front** | `TileLayer::Front` | 前景、建筑 | 树木、房屋、火把 |

**渲染顺序**: Back → Middle → Front（由远到近）

### 2.3 网格系统

**网格尺寸**: 
- `CELL_WIDTH = 48` 像素
- `CELL_HEIGHT = 32` 像素

**格子坐标 → 世界坐标**:
```rust
world_x = grid_x * CELL_WIDTH   // 例：grid_x=10 → world_x=480
world_y = grid_y * CELL_HEIGHT  // 例：grid_y=20 → world_y=640
```

### 2.4 动画瓦片

**组件结构**:
```rust
pub struct AnimatedTile {
    pub frame_count: u16,           // 总帧数
    pub frame_interval: u16,        // 帧间隔（毫秒）
    pub base_image_index: u16,      // 起始图像索引
    // 运行时状态由 AnimationSystem 管理
}
```

**播放控制**: 
- `show_animations`: 控制动画播放/暂停（A键）
- `show_animated_tiles`: 控制动画瓦片显示/隐藏（D键）

## 坐标系统

### 3.1 坐标类型

系统使用三种坐标系统：

| 坐标类型 | 定义 | 用途 |
|---------|------|------|
| **格子坐标** | `(grid_x, grid_y)` | 地图数据存储 |
| **世界坐标** | `(world_x, world_y)` | 物理位置计算 |
| **屏幕坐标** | `(screen_x, screen_y)` | 最终渲染位置 |

### 3.2 坐标转换

#### 格子 → 世界

```rust
world_x = grid_x * CELL_WIDTH;
world_y = grid_y * CELL_HEIGHT;
```

#### 世界 → 屏幕

```rust
screen_x = (world_x - camera_pos.x) * camera.zoom + camera.screen_width / 2.0;
screen_y = (world_y - camera_pos.y) * camera.zoom + camera.screen_height / 2.0;
```

**参数说明**:
- `camera_pos`: 相机在世界中的位置
- `camera.zoom`: 缩放级别（1.0 = 100%）
- `camera.screen_width/height`: 屏幕尺寸

### 3.3 坐标原点

- **格子坐标**: 左上角 (0, 0)
- **世界坐标**: 左上角 (0, 0)
- **屏幕坐标**: 中心点 (screen_width/2, screen_height/2)

## 渲染流程

### 4.1 主渲染循环

```
┌─────────────────────────────────────┐
│  1. 获取相机和渲染配置              │
├─────────────────────────────────────┤
│  2. 计算视口范围（世界坐标）        │
├─────────────────────────────────────┤
│  3. 按层级循环（Back→Middle→Front）│
│     ├─ 3.1 检查层级是否启用         │
│     ├─ 3.2 收集静态瓦片             │
│     ├─ 3.3 收集动画瓦片             │
│     └─ 3.4 渲染所有瓦片             │
├─────────────────────────────────────┤
│  4. 返回渲染结果                    │
└─────────────────────────────────────┘
```

### 4.2 视口计算

```rust
// 相机视野范围（世界坐标）
let half_width = (camera.screen_width / 2.0) / camera.zoom;
let half_height = (camera.screen_height / 2.0) / camera.zoom;

let view_left = camera_pos.x - half_width;
let view_right = camera_pos.x + half_width;
let view_top = camera_pos.y - half_height;
let view_bottom = camera_pos.y + half_height;
```

**为什么除以zoom?**
- `zoom=2.0` 时，相机拉近，实际看到的世界范围缩小一半
- `zoom=0.5` 时，相机拉远，实际看到的世界范围扩大两倍

## 层级渲染

### 5.1 渲染顺序

**固定顺序**: Back → Middle → Front

```rust
let layers = [
    (TileLayer::Back, config.show_back),
    (TileLayer::Middle, config.show_middle),
    (TileLayer::Front, config.show_front),
];

for (layer, should_show) in layers.iter() {
    if !should_show { continue; }
    // 渲染该层...
}
```

### 5.2 层级独立控制

用户可通过键盘切换各层显示：

| 按键 | 层级 | 功能 |
|------|------|------|
| `1` | Front | 切换前景层 |
| `2` | Middle | 切换中间层 |
| `3` | Back | 切换背景层 |

**实现**: `RenderConfig` 组件的 `show_back/show_middle/show_front` 字段

### 5.3 视口裁剪差异

不同层级使用不同的视口扩展：

```rust
let bottom_extra = if matches!(layer, TileLayer::Front) {
    800.0  // Front 层底部额外扩展 800 像素
} else {
    200.0  // Back/Middle 层保持 200 像素
};
```

**原因**: Front层建筑物高度可达数百像素，需要更大的底部缓冲区。

## 瓦片偏移计算

### 6.1 偏移规则总结

| 层级 | 标准尺寸 | 非标准尺寸 | 公式 |
|------|----------|------------|------|
| **Back** | `y * 32` | `y * 32` | `world_y` |
| **Middle** | `y * 32` | `(y+1)*32 - height` | `world_y + 32 - h` |
| **Front** | `y * 32` | 见下表 | 复杂规则 |

### 6.2 Front层偏移详解

Front层偏移取决于**尺寸、混合模式、库索引**：

| 条件 | 偏移公式 | 用途 |
|------|---------|------|
| 标准尺寸 | `y * 32` | 小装饰物 |
| 非标准 + Blend + 特殊库 (14/27/100-199) | `y*32 - 64` | 火把、蜡烛等光效 |
| 非标准 + 其他 | `(y+1)*32 - height` | 建筑、树木 |

**代码实现**:

```rust
let adjusted_y = if matches!(layer, TileLayer::Back) {
    // Back层: 永远直接使用Y坐标
    world_y
} else if is_standard_size {
    // 标准尺寸: 直接使用Y坐标
    world_y
} else {
    // 非标准尺寸偏移计算
    if matches!(layer, TileLayer::Front) && use_blend {
        if lib_index == 14 || lib_index == 27 || (lib_index > 99 && lib_index < 199) {
            // 特殊库: 灯光效果偏移
            world_y - (2 * CELL_HEIGHT) as f32
        } else {
            // 普通混合
            world_y + CELL_HEIGHT as f32 - tile_h as f32
        }
    } else {
        // 非 blend 或非 Front 层
        world_y + CELL_HEIGHT as f32 - tile_h as f32
    }
};
```

### 6.3 标准尺寸定义

```rust
let is_standard_size = 
    (tile_w == 48 && tile_h == 32) ||  // 1x1 格子
    (tile_w == 96 && tile_h == 64);    // 2x2 格子
```

## 图像内部偏移

### 7.1 什么是图像内部偏移

**定义**: 图库中每个图像内置的偏移量 `(info.x, info.y)`，用于精确定位图像。

**来源**: 图库文件 (`.wil/.wzl`) 中的 `ImageInfo` 结构体字段。

### 7.2 偏移应用规则

**仅在以下情况应用**:

| 条件 | 说明 |
|------|------|
| Front层 + Blend + 特殊库 (14/27/100-199) | 火把、蜡烛等光效 |
| Front层 + Blend + 特定索引 (2723-2732) | 特殊动画 |
| 库28 + 非空偏移 | 特殊装饰 |

**其他情况不应用偏移**，包括：
- Back层所有瓦片
- Middle层所有瓦片
- Front层非混合瓦片
- Front层普通混合瓦片

### 7.3 代码实现

```rust
let should_apply_offset = if matches!(layer, TileLayer::Front) {
    if use_blend {
        // Blend tiles: special libs OR specific indices
        lib_index == 14 || lib_index == 27 || 
        (lib_index > 99 && lib_index < 199) ||
        (img_index >= 2723 && img_index <= 2732)
    } else if lib_index == 28 {
        // Lib 28: apply offset if non-empty
        info.x != 0 || info.y != 0
    } else {
        false
    }
} else {
    // Back/Middle layers: never apply offset
    false
};

let (adjusted_x_final, adjusted_y_final) = if should_apply_offset {
    (adjusted_x + info.x as f32, adjusted_y + info.y as f32)
} else {
    (adjusted_x, adjusted_y)
};
```

### 7.4 历史问题

**错误做法**: 对所有瓦片应用偏移
```rust
// ❌ 错误 - 导致Back层错位
let adjusted_x_with_offset = adjusted_x + info.x as f32;
let adjusted_y_with_offset = adjusted_y + info.y as f32;
```

**正确做法**: 条件判断
```rust
// ✅ 正确 - 仅特定情况应用
let (x, y) = if should_apply_offset {
    (adjusted_x + info.x as f32, adjusted_y + info.y as f32)
} else {
    (adjusted_x, adjusted_y)
};
```

## 混合模式

### 8.1 混合模式类型

| 模式 | 用途 | 效果 |
|------|------|------|
| **Normal** | 普通瓦片 | 标准Alpha混合 |
| **ADD** | 发光效果 | 叠加发光（火焰、灯光） |

### 8.2 使用场景

**ADD混合**: 
- 火把 (库14)
- 蜡烛 (库27)
- 其他光效 (库100-199)
- 特殊动画 (索引2723-2732)

**Normal混合**: 
- 所有其他瓦片

### 8.3 代码实现

```rust
// 保存旧混合模式
let old_blend_mode = if use_blend {
    let current = canvas.blend_mode();
    canvas.set_blend_mode(ggez::graphics::BlendMode::ADD);
    Some(current)
} else {
    None
};

// 绘制瓦片
canvas.draw(image, DrawParam::default()...);

// 恢复原混合模式
if let Some(old_mode) = old_blend_mode {
    canvas.set_blend_mode(old_mode);
}
```

### 8.4 混合模式效果

```
Normal混合: 
  result = src.rgb * src.a + dst.rgb * (1 - src.a)
  
ADD混合:
  result = src.rgb * src.a + dst.rgb
  (越叠加越亮，产生发光效果)
```

## 视口裁剪

### 9.1 裁剪原理

**目标**: 只渲染屏幕可见范围内的瓦片，减少GPU压力。

**方法**: 计算瓦片世界坐标，与视口范围比较。

### 9.2 裁剪边界

```rust
// 瓦片世界坐标
let world_x = (tile.grid_x * CELL_WIDTH) as f32;
let world_y = (tile.grid_y * CELL_HEIGHT) as f32;

// Front层底部扩展更大
let bottom_extra = if matches!(layer, TileLayer::Front) {
    800.0
} else {
    200.0
};

// 裁剪判断
if world_x > view_right + 200.0
    || world_x < view_left - 200.0
    || world_y > view_bottom + bottom_extra
    || world_y < view_top - 200.0
{
    continue;  // 跳过不可见瓦片
}
```

### 9.3 为什么需要边界缓冲

**边界扩展** (200px / 800px):
- 防止瓦片边缘突然出现/消失
- 高大建筑物（Front层）需要更大底部缓冲
- 相机移动时提供平滑过渡

### 9.4 优化效果

假设地图 700x700 格子:
- **无裁剪**: 渲染 490,000 个瓦片
- **有裁剪**: 仅渲染 ~2,000 个瓦片（视口大小）
- **性能提升**: ~245倍

## 动画系统

### 10.1 静态与动画瓦片

**静态瓦片**: 
- 只有 `MapTile` 组件
- 永久显示同一图像

**动画瓦片**:
- 同时拥有 `MapTile` + `AnimatedTile` 组件
- 图像索引随时间变化

### 10.2 独立开关

系统提供两个独立开关：

| 开关 | 字段 | 按键 | 功能 |

**当前实现**: 简化版，使用基础图像索引

**完整实现** (由AnimationSystem管理):
```rust
current_frame = (elapsed_time / frame_interval) % frame_count;

```

### 10.4 防止重复绘制


## 碰撞层渲染

### 11.1 碰撞数据存储

**位置**: `MapCell.back_image` 的第29位

```rust
let has_obstacle = (cell.back_image & 0x20000000) != 0;
```

**含义**:
- `bit 29 = 1`: 该格子不可通行（障碍物）
- `bit 29 = 0`: 该格子可通行

### 11.2 碰撞层偏移

**规则**: 向下偏移一个格子（32像素）

```rust
// 计算世界坐标（向下偏移一个格子，即32px）
let world_x = (grid_x * CELL_WIDTH) as f32;
let world_y = ((grid_y + 1) * CELL_HEIGHT) as f32;  // +1 = 向下偏移
```

**原因**: 
- 碰撞判定基于角色脚底位置
- 格子中心在 `(grid_x, grid_y)`
- 脚底位置在 `(grid_x, grid_y+1)`

### 11.3 可视化渲染

```rust
// 绘制暗红色半透明矩形
let obstacle_color = Color::from_rgba(180, 0, 0, 120);

let rect = ggez::graphics::Rect::new(
    screen_x,
    screen_y,
    CELL_WIDTH as f32 * camera.zoom,
    CELL_HEIGHT as f32 * camera.zoom,
);

let mesh = Mesh::new_rectangle(ctx, DrawMode::fill(), rect, obstacle_color)?;
canvas.draw(&mesh, DrawParam::default());
```

### 11.4 开关控制

**按键**: `O`

**实现**: `RenderConfig.show_obstacles`

## 性能优化

### 12.1 已实现的优化

| 优化技术 | 说明 | 效果 |
|---------|------|------|
| **视口裁剪** | 只渲染可见瓦片 | 减少99%渲染量 |
| **批量绘制** | 收集后统一绘制 | 减少Draw Call |
| **纹理缓存** | 图像预加载到GPU | 避免重复上传 |
| **层级过滤** | 跳过隐藏层 | 减少CPU计算 |
| **HashSet查重** | 防止重复绘制动画瓦片 | 避免重复渲染 |

### 12.2 渲染统计

**典型场景** (700x700地图，1600x1200窗口):
- 总瓦片数: ~280,000
- 可见瓦片数: ~2,500
- 渲染率: 0.89%
- 帧率: 60 FPS

### 12.3 性能瓶颈

1. **纹理切换**: 不同图库瓦片交替绘制
2. **混合模式切换**: ADD/Normal频繁切换
3. **CPU查询**: ECS查询瓦片实体

### 12.4 未来优化方向

- [ ] **瓦片批处理**: 相同图库瓦片合批
- [ ] **实例化渲染**: GPU实例化绘制
- [ ] **空间索引**: 四叉树加速查询
- [ ] **异步加载**: 后台线程准备纹理

## 总结

地图渲染系统是游戏视觉呈现的核心，通过**分层渲染、视口裁剪、混合模式、精确偏移计算**等技术，实现了高性能、高质量的地图显示。系统完全遵循C#原版逻辑，确保渲染效果一致。

**关键要点**:
1. ✅ 三层架构（Back/Middle/Front）按顺序渲染
2. ✅ 视口裁剪减少99%渲染量
3. ✅ 条件偏移确保各层对齐正确
4. ✅ 图像内部偏移仅用于特定情况（火把等）
5. ✅ 混合模式实现发光效果
6. ✅ 碰撞层向下偏移32px显示

**调试技巧**:
- 按 `1/2/3` 独立查看各层
- 按 `S/D` 分离静态/动画瓦片
- 按 `O` 检查碰撞层对齐
- 按 `G` 显示网格辅助定位

**常见问题**:
- ❌ Back层错位 → 检查是否错误应用图像偏移
- ❌ 光效偏移 → 确认库索引和混合模式
- ❌ 建筑悬空 → 检查非标准尺寸偏移计算
- ❌ 碰撞层错位 → 确认向下偏移32px
