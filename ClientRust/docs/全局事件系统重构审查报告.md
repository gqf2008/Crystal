### 2.1 事件流设计

#### ✅ 优点

**1. 清晰的单向数据流**
```
ggez EventHandler (GameState)
    ↓ (统一接收)
GlobalEvents 组件 (ECS World)
    ↓ (各系统读取)
Scene.handle_input_event()
    ↓ (处理业务逻辑)
网络命令 / UI更新
```

**2. 符合ECS架构原则**
- 事件作为组件 (`GlobalEvents`)
- 场景作为系统 (消费事件)
- 数据与逻辑分离

**3. 责任明确划分**
```rust
// GameState: 只负责事件收集
impl EventHandler for GameState {
    fn key_down_event(&mut self, ...) -> GameResult {
        self.world.query_mut::<&mut GlobalEvents>()
            .next()
            .events.input_events.push(InputEvent::KeyDown { ... });
        Ok(())
    }
}

// Scene: 只负责事件消费和业务逻辑
impl Scene for LoginScene {
    fn update(&mut self, ctx: &mut Context, world: &mut World) -> GameResult<Option<SceneType>> {
        self.handle_input_event(ctx, world)?;  // 从GlobalEvents读取
        self.handle_network_event(world);       // 从GlobalEvents读取
        Ok(None)
    }
}
```

```rust
        self.net_events.clear();      // O(1) 11个Vec::clear()

    }
}
```

### ✅ 优化建议1: 事件收集辅助方法

**建议实现**:
```rust
impl GameState {
    /// 辅助方法: 向GlobalEvents添加输入事件
    #[inline]
    fn push_input_event(&mut self, event: InputEvent) {
        if let Some((_, events)) = self.world.query_mut::<&mut GlobalEvents>().into_iter().next() {
            events.input_events.push(event);
        } else {
            tracing::error!("❌ GlobalEvents component not found!");
        }
    }
}

// 简化EventHandler实现:
fn key_down_event(&mut self, _ctx: &mut Context, input: KeyInput, repeated: bool) -> GameResult {

        repeat: repeated,
        text: input.event.text,
        timestamp: Instant::now(),
    });
    Ok(())
}
```
