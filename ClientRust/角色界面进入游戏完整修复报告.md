## 📋 问题概述

### 原始错误
从角色选择界面点击"开始游戏"按钮时，程序崩溃并出现以下错误:

```
Parameter `Res<MapData>` failed validation: Resource does not exist
Parameter `ResMut<ChatManager>` failed validation: Resource does not exist  
Parameter `ResMut<MLibraryAssets>` failed validation: Resource does not exist
```

---

## 🔍 根本原因分析

### 问题 1: 资源初始化顺序问题
**症状**: `MapData` 资源不存在  
**原因**: `create_map_layers_system` 在 `setup_game_scene` 之前或并行运行  
**根本原因**: `OnEnter(GameState::Game)` 中的系统是并行运行的,没有保证执行顺序

### 问题 2: 资源未创建
**症状**: `ChatManager` 资源不存在  
**原因**: `setup_chat_system` 只初始化了其他资源,没有创建 `ChatManager`

### 问题 3: 资源访问冲突
**症状**: `MLibraryAssets` 资源不存在  
**原因**: `render_map_system` 使用 `ResMut` 独占访问,可能被其他系统占用

## 📝 技术要点

### 1. Bevy 系统执行顺序
- **并行执行**: 默认情况下,同一调度阶段的系统并行运行
- **顺序执行**: 使用 `.chain()` 确保顺序
- **依赖管理**: 如果系统 B 需要系统 A 的输出,必须使用 chain

### 2. 资源访问模式
- **Res<T>**: 只读访问,允许多个系统同时读取
- **ResMut<T>**: 可写访问,独占,只允许一个系统访问
- **Option<Res<T>>**: 资源可能不存在时使用
- **Option<ResMut<T>>**: 资源可能不存在或被占用时使用

### 3. OnEnter 生命周期
- **触发时机**: 状态切换时立即执行
- **执行次数**: 每次进入状态执行一次
- **清理**: 配合 OnExit 实现完整的生命周期管理
