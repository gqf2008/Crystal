# 原地不动问题修复

## 问题描述
角色按住鼠标移动一段时间后，会突然原地不动，无法继续移动。

## 问题原因

### 根本原因：时间系统初始化逻辑错误

在基于时间的移动系统中，存在两个关键bug：

#### Bug 1: 初始化时间计算错误
```rust
// ❌ 错误的代码
let last_move = unsafe { LAST_MOVE_TIME.unwrap_or(now) };
let elapsed_ms = now.duration_since(last_move).as_millis() as u64;
```

**问题分析**：
- `LAST_MOVE_TIME` 初始为 `None`
- 第一次调用时，`unwrap_or(now)` 返回当前时间 `now`
- 这导致 `elapsed_ms = now - now = 0`
- 因此 `elapsed_ms >= WALK_INTERVAL_MS (500ms)` 永远为 `false`
- 角色无法开始第一次移动

#### Bug 2: 停止后时间未重置
```rust
// ❌ 错误的逻辑
} else {
    // 已到达目标位置,停止
    user.player.set_current_action(MirAction::Standing);
    // ⚠️ 问题：LAST_MOVE_TIME 没有重置！
}
```

**问题分析**：
- 当角色到达目标或碰到障碍物时停止
- `LAST_MOVE_TIME` 保留着上次移动的时间
- 下次开始移动时，`elapsed_ms` 计算的是从上次移动到现在的时间
- 这个时间可能非常大（例如5秒），导致立即触发移动
- 但后续的移动又会因为时间过长而出现异常

## 修复方案

### 修复1: 正确初始化时间

```rust
// ✅ 修复后的代码
let last_move = unsafe { 
    if LAST_MOVE_TIME.is_none() {
        // 第一次初始化为当前时间
        LAST_MOVE_TIME = Some(now);
    }
    LAST_MOVE_TIME.unwrap()
};
let elapsed_ms = now.duration_since(last_move).as_millis() as u64;
```

**修复说明**：
- 第一次调用时，显式初始化 `LAST_MOVE_TIME = Some(now)`
- 之后 `elapsed_ms` 会正常累积
- 当 `elapsed_ms >= 500ms` 时，触发第一次移动

### 修复2: 停止后重置时间

```rust
// ✅ 修复后的代码
} else {
    // 已到达目标位置,停止
    if let Some(ref mut user) = self.user {
        user.player.set_current_action(MirAction::Standing);
        user.player.map_object.offset_move.x = 0;
        user.player.map_object.offset_move.y = 0;
    }
    self.blocked_cell = None;
    // ✅ 重置时间，准备下次移动
    unsafe { LAST_MOVE_TIME = None; }
}

// 鼠标没按下
} else {
    // 停止移动
    // ...
    // ✅ 重置时间，准备下次移动
    unsafe { LAST_MOVE_TIME = None; }
}
```

**修复说明**：
- 当角色停止移动时（到达目标、碰到障碍物、松开鼠标），重置 `LAST_MOVE_TIME = None`
- 下次开始移动时，时间会从头开始计算
- 确保每次移动都是从0开始累积时间

## 时间系统工作流程

### 正确的时间流程

```
开始移动:
  ├─ LAST_MOVE_TIME = None
  ├─ 第一帧: 初始化 LAST_MOVE_TIME = now
  ├─ elapsed_ms = 0
  └─ 不触发移动（< 500ms）

持续移动:
  ├─ 第二帧: elapsed_ms = 16ms (约1帧)
  ├─ 第三帧: elapsed_ms = 33ms (约2帧)
  ├─ ...
  ├─ 第30帧: elapsed_ms = 500ms ✅
  │   └─ 触发移动！更新位置，重置 LAST_MOVE_TIME = now
  └─ 循环...

停止移动:
  ├─ 到达目标 / 碰到障碍物 / 松开鼠标
  ├─ 切换为 Standing
  └─ 重置 LAST_MOVE_TIME = None ✅

再次开始移动:
  └─ 从头开始计算时间（回到"开始移动"）
```

## 相关问题回顾

这个bug是在修复"FPS影响移动速度"问题时引入的：

### 之前的系统（基于帧数）
```rust
static mut MOVE_TIMER: u32 = 0;
MOVE_TIMER += 1;  // 每帧递增

if MOVE_TIMER % WALK_INTERVAL == 0 {
    // 移动
}
```
- ✅ 不会卡住（计数器一直递增）
- ❌ 速度受FPS影响

### 改进后的系统（基于时间）
```rust
let elapsed_ms = now - last_move;

if elapsed_ms >= WALK_INTERVAL_MS {
    // 移动
}
```
- ✅ 速度不受FPS影响
- ⚠️ 需要正确管理时间状态（本次修复的内容）

## 经验教训

1. **状态管理很重要**：基于时间的系统需要小心管理时间状态的初始化和重置
2. **边界条件测试**：要测试"第一次"、"停止后重新开始"等边界情况
3. **不要假设初始值**：`Option::unwrap_or()` 虽然方便，但要注意默认值是否合理

## 未来优化建议

可以考虑使用更清晰的状态机：

```rust
enum MoveState {
    Idle,
    Moving { start_time: Instant },
}

// 使用
match self.move_state {
    MoveState::Idle => {
        // 开始移动
        self.move_state = MoveState::Moving { start_time: now };
    }
    MoveState::Moving { start_time } => {
        let elapsed = now - start_time;
        if elapsed >= interval {
            // 移动并重置
            self.move_state = MoveState::Moving { start_time: now };
        }
    }
}
```

这样状态转换会更清晰，不容易出错。
