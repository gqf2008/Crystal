# 游戏场景渲染修复总结

## 🎉 已完成的修复

### 1. **地图显示黑屏问题** ✅ 已解决
**问题原因**：UserInformation 事件在 SelectScene 阶段到达，但切换到 GameScene 后没有被重新发送。

**解决方案**：
- 在 `Program` 中添加 `cached_user_info` 字段缓存 UserInformation
- 在场景切换时（Select → Game）重发缓存的 MapInformation 和 UserInformation
- GameScene 正确处理这两个事件并转换状态到 Ready

**关键代码**：
```rust
// src/program.rs
pub struct CrystalGame {
    pub cached_map_info: Option<(i32, String, String)>,
    pub cached_user_info: Option<Box<mir2_shared::packets::server::UserInformation>>, // ⭐ 新增
}

// 场景切换时重发
if let Some(ref user_info) = self.cached_user_info {
    let event = GameEvent::UserInformation {
        user_info: user_info.clone(),
    };
    scene_manager.process_event(&event);
}
```

### 2. **状态机实现** ✅ 完成
**GameSceneState 枚举**：
- `WaitingForData` - 等待服务器数据
- `LoadingMap(String)` - 正在加载地图
- `WaitingForPlayer` - 等待角色数据
- `Ready` - 准备就绪，正常渲染

**状态转换流程**：
```
WaitingForData 
  → MapInformation 到达 → LoadingMap("map.map")
  → 地图加载完成 → WaitingForPlayer
  → UserInformation 到达 → Ready ✅
```

## ⚠️ 待解决的问题

### 问题1: 登录背景纹理残留 🔴 当前问题

**现象**：
切换到游戏场景后，登录场景的背景纹理仍然显示在屏幕上。

**分析**：
1. Canvas 在每帧开始时通过 `Canvas::from_frame(ctx, bg_color)` 清除
2. `bg_color = Color::from_rgb(0, 32, 0)` (深绿色)
3. 但登录场景绘制的纹理可能以某种方式持久化

**可能的原因**：
- ❓ LoginScene 将纹理绘制到了 GPU 缓存
- ❓ Canvas 清除没有正确生效
- ❓ LoginScene 和 GameScene 使用了不同的 Canvas 层

**调试步骤**：
1. ✅ 确认 Canvas 每帧都重新创建（已确认）
2. ✅ 确认 bg_color 正确设置（已确认）
3. ⏳ 检查 LoginScene 是否使用了特殊的绘制方法
4. ⏳ 检查是否有纹理缓存未清理

**建议的解决方案**：

#### 方案A: 强制清除 Canvas（最简单）
在 GameScene.draw() 开始时添加：
```rust
// 清除整个屏幕为深绿色
canvas.set_default_filter(ggez::graphics::FilterMode::Nearest);
```

**注意**：这个方案已经在代码中实现了，但可能需要进一步检查。

#### 方案B: 在场景切换时显式清理资源
在 `check_select_to_game_transition()` 中添加：
```rust
// 清理 SelectScene 的资源
drop(scene_manager.current_scene);
scene_manager.switch_scene(SceneType::Game)?;
```

#### 方案C: 使用独立的 Canvas Target
为每个场景创建独立的 Canvas Target，避免互相影响。

### 推荐操作步骤

1. **检查是否真的是登录背景纹理**
   - 截图或描述看到的具体内容
   - 确认是哪个纹理（Prguse 65？）

2. **测试 Canvas 清除是否生效**
   在 GameScene.draw() 开始时添加测试代码：
   ```rust
   // 测试：强制清除为纯红色
   use ggez::graphics::{Color, Rect, DrawMode, Mesh};
   let test_color = Color::from_rgb(255, 0, 0); // 纯红色
   let test_rect = Rect::new(0.0, 0.0, screen_width, screen_height);
   let test_mesh = Mesh::new_rectangle(ctx, DrawMode::fill(), test_rect, test_color)?;
   canvas.draw(&test_mesh, DrawParam::default());
   ```
   
   如果看到红色背景 → Canvas 清除工作正常，问题在 LoginScene
   如果看到登录纹理 → Canvas 清除有问题

3. **检查 LoginScene 的绘制代码**
   查找是否有以下代码：
   ```rust
   canvas.set_screen_coordinates(...); // 可能导致坐标系残留
   canvas.set_default_filter(...);      // 可能导致过滤器设置残留
   ```

## 🔧 技术细节

### Canvas 创建流程
```rust
// src/program.rs::draw()
let bg_color = Color::from_rgb(0, 32, 0);
let mut canvas = Canvas::from_frame(ctx, bg_color);
```

**说明**：
- `Canvas::from_frame()` 会创建一个新的 Canvas 并清除为 bg_color
- 每帧都会重新创建，理论上不会有残留
- bg_color 是传奇2的深绿色 (0, 32, 0)

### 场景切换流程
```
1. SelectScene 检测到 pending_scene_change == Some(SceneType::Game)
2. Program::check_select_to_game_transition() 被调用
3. SceneManager::switch_scene(SceneType::Game)
4. GameScene::initialize() 创建新场景
5. 重发缓存的 MapInformation
6. 重发缓存的 UserInformation ⭐
7. GameScene 状态转换到 Ready
8. 开始正常渲染
```
