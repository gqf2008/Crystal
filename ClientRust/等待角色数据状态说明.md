# "等待角色数据" 状态说明

**状态**: 游戏场景显示 "等待角色数据..."
**原因**: 正常的加载流程，等待服务器发送 UserInformation 数据包
**时间**: 2024年

---

## 一、状态说明

### 这是正常现象！

您看到 "等待角色数据..." 说明：

✅ **LoginScene → SelectScene 成功**  
✅ **SelectScene → GameScene 成功**  
✅ **地图信息已收到** (MapInformation)  
✅ **地图文件已加载** (0.map 或其他)  
⏳ **正在等待** UserInformation 数据包  

### 当前状态机流程

```
1. WaitingForData (等待服务器数据...)
   ↓
2. LoadingMap (正在加载地图: 0.map)  ✅ 已完成
   ↓
3. WaitingForPlayer (等待角色数据...)  ⬅️ 您在这里
   ↓
4. Ready (正常游戏渲染)  ⏳ 等待触发
```

---

## 二、预期行为

### 正常情况

服务器应该在 1-3 秒内发送 `UserInformation` 数据包，包含：
- 玩家 ObjectID
- 玩家名称
- 职业、性别、等级
- 当前位置 (X, Y 坐标)
- 装备、背包、金币等

收到后，状态会自动切换到 `Ready`，开始渲染游戏画面。

### 如果一直卡在这个状态

可能的原因：

**A. 服务器未发送 UserInformation**
- 检查服务器日志，确认是否发送了角色数据
- 检查网络连接是否正常

**B. 客户端未收到数据包**
- 检查网络管道是否正常
- 查看控制台日志是否有网络错误

**C. UserInformation 处理出错**
- 检查控制台是否有错误日志
- 查看是否有字段解析失败

**正常显示**:
- 黑色背景
- 大号白色中文: "等待角色数据..."

**如果不正常**:
- 乱码 → 参考 `中文字体乱码修复说明.md`

**异常**: 超过 10 秒仍然显示 "等待角色数据..."

如果超过 10 秒，请检查服务器和网络。

## 五、服务器端检查

### 检查服务器是否发送了 UserInformation

**位置**: 服务器代码中查找 `UserInformation` 或 `SendUserInfo`

**预期行为**:
1. 客户端选择角色后，发送 `StartGame` 请求
2. 服务器收到后，发送 `MapInformation`
3. 服务器紧接着发送 `UserInformation`
4. 客户端收到后，创建玩家对象，切换到 Ready 状态

**服务器日志应该显示**:
```
[INFO] Player selected character: XXX
[INFO] Sending MapInformation: 0.map
[INFO] Sending UserInformation: ObjectID=12345, Name=XXX
```

如果服务器没有发送 UserInformation，检查服务器代码逻辑。

```rust
fn draw(&mut self, ctx: &mut ggez::Context, canvas: &mut Canvas) {
```

```rust
    static mut WAIT_COUNTER: u32 = 0;
    unsafe {
        WAIT_COUNTER += 1;
        if WAIT_COUNTER > 600 && self.state == GameSceneState::WaitingForPlayer {
            tracing::warn!("⚠️ 等待超时，强制切换到 Ready 状态");
            self.state = GameSceneState::Ready;
        }
    }
    
    // ... 继续正常流程
}
```

**效果**: 如果等待超过 10 秒 (600 帧 / 60fps = 10秒)，强制切换到 Ready 状态。

## 七、常见问题 FAQ

### Q1: 为什么要等待角色数据?

**A**: 因为渲染玩家需要完整的角色信息：
- 位置坐标 → 确定摄像机位置
- 职业/性别 → 加载正确的角色纹理
- 等级/装备 → 显示正确的外观
- HP/MP → 显示生命值和魔法值

没有这些数据，无法正确显示玩家角色。

---

### Q2: 地图数据和角色数据哪个先到?

**A**: **不确定**！服务器可能先发 MapInformation，也可能先发 UserInformation。

我们的状态机设计可以处理任意顺序：
- MapInfo 先到 → LoadingMap → WaitingForPlayer → Ready
- UserInfo 先到 → 等待地图加载完成 → Ready
- 同时到 → 直接 Ready

---

### Q3: 可以跳过这个等待吗?

**A**: **不建议**！

如果跳过等待，会导致：
- 摄像机位置错误 (0, 0)
- 没有玩家角色显示
- 无法交互
- 可能崩溃

除非用于测试地图渲染，否则必须等待完整数据。

---

### Q4: 如何知道服务器是否正常运行?

**A**: 检查以下几点：

1. **服务器进程是否运行**
   ```powershell
   Get-Process | Where-Object {$_.ProcessName -like "*Server*"}
   ```

2. **服务器日志是否有错误**
   - 查看服务器控制台输出
   - 检查日志文件

3. **网络连接是否正常**
   - 客户端显示 "✅ Connected to server successfully!"
   - 能够登录和选择角色

如果这些都正常，但仍然卡在 "等待角色数据"，检查服务器的 `UserInformation` 发送逻辑。
