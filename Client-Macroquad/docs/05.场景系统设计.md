# 场景系统设计

## 🎯 设计目标

创建一个清晰、简洁的场景管理系统，支持：
- 登录界面（UI 为主）
- 角色选择界面（UI 为主）
- 游戏主场景（ECS + UI）
- 加载场景（可选）

## 🏗️ 架构设计

### 核心理念

**GameState 是唯一的场景管理器**，而不是单独的 SceneManager。

**原因**：
1. ✅ **避免重复**：GameState 本身就是游戏的顶层状态，自然应该管理场景
2. ✅ **资源共享**：网络、配置、资源缓存等全局资源直接在 GameState 中
3. ✅ **更简洁**：减少一层抽象，代码更直观
4. ✅ **符合直觉**：游戏状态 = 当前场景 + 全局资源

### 结构图

```
┌─────────────────────────────────────────┐
│          GameState (游戏状态)            │
├─────────────────────────────────────────┤
│  - current_scene: Box<dyn Scene>        │  ← 当前场景
│  - network: NetworkContext              │  ← 全局网络
│  - settings: Settings                   │  ← 全局配置
│  - resources: ResourceManager           │  ← 全局资源
│  - font: Font                           │  ← 共享字体
└─────────────────────────────────────────┘
               ↓ 场景切换
    ┌──────────┴──────────┐
    │                     │
┌───▼────┐      ┌─────────▼────────┐      ┌──────────▼────┐
│ Login  │  →   │ CharacterSelect  │  →   │  GameScene    │
│ Scene  │      │     Scene        │      │  (ECS World)  │
└────────┘      └──────────────────┘      └───────────────┘
```

## 📦 模块职责

### 1. GameState（游戏状态管理器）

**职责**：
- ✅ 持有当前场景
- ✅ 管理场景切换
- ✅ 提供全局资源访问
- ✅ 统一的游戏循环入口

**代码示例**：
```rust
pub struct GameState {
    current_scene: Box<dyn Scene>,
    pending_transition: Option<SceneTransition>,
    
    // 全局资源
    pub network: NetworkContext,
    pub settings: Settings,
    pub resources: ResourceManager,
    pub font: Option<Font>,
}

impl GameState {
    pub async fn new() -> GameResult<Self> {
        // 初始化全局资源
        // 创建初始场景（登录界面）
    }
    
    pub fn update(&mut self, dt: f32) -> GameResult { ... }
    pub fn render(&mut self) -> GameResult { ... }
    pub fn process_scene_transition(&mut self) -> GameResult { ... }
}
```

### 2. Scene Trait（场景接口）

**职责**：
- ✅ 定义场景的生命周期
- ✅ 场景之间通过 SceneTransition 通信

**代码示例**：
```rust
pub trait Scene {
    fn name(&self) -> &str;
    fn on_enter(&mut self) -> GameResult;
    fn on_exit(&mut self) -> GameResult;
    fn update(&mut self, dt: f32) -> GameResult<SceneTransition>;
    fn render(&mut self) -> GameResult;
    fn handle_input(&mut self) -> GameResult;
}
```

### 3. SceneTransition（场景切换）

**职责**：
- ✅ 定义场景切换的所有可能性
- ✅ 携带场景切换所需的数据

**代码示例**：
```rust
pub enum SceneTransition {
    None,
    Login,
    CharacterSelect { account: String },
    Game { character_id: u32, character_name: String },
    Loading { next_scene: Box<SceneTransition>, progress_text: String },
    Exit,
}
```

## 🎮 场景实现

### 1. LoginScene（登录界面）

**特点**：
- UI 为主，无 ECS
- 账号/密码输入
- 连接服务器

**状态**：
```rust
pub struct LoginScene {
    account_input: String,
    password_input: String,
    focused_input: usize,
    login_state: LoginState,
    error_message: Option<String>,
    font: Option<Font>,
}
```

**切换逻辑**：
```rust
// 登录成功 → 角色选择
Ok(SceneTransition::CharacterSelect {
    account: self.account_input.clone(),
})
```

### 2. CharacterSelectScene（角色选择）

**特点**：
- UI 为主，简单展示
- 显示角色列表
- 创建/删除角色

**状态**：
```rust
pub struct CharacterSelectScene {
    account: String,
    characters: Vec<CharacterInfo>,
    selected_index: Option<usize>,
    font: Option<Font>,
}
```

**切换逻辑**：
```rust
// 选择角色 → 游戏场景
Ok(SceneTransition::Game {
    character_id: character.id,
    character_name: character.name.clone(),
})
```

### 3. GameScene（游戏主场景）

**特点**：
- **完整的 ECS 系统**
- 地图渲染
- 实体管理
- UI 覆盖层

**状态**：
```rust
pub struct GameScene {
    character_id: u32,
    character_name: String,
    ctx: GameContext,          // 包含 ECS World
    scheduler: SystemScheduler, // 系统调度器
    font: Option<Font>,
    show_debug: bool,
}
```

**职责**：
- ✅ 运行所有游戏系统（物理、渲染、AI 等）
- ✅ 绘制地图和实体
- ✅ 绘制 UI 覆盖层（血条、技能栏等）

### 4. LoadingScene（加载场景）

**特点**：
- 显示加载进度
- 异步加载资源
- 完成后切换到目标场景

**状态**：
```rust
pub struct LoadingScene {
    next_scene: SceneTransition,
    progress: f32,
    progress_text: String,
    loading_complete: bool,
}
```

## 💡 设计优势

### vs. SceneManager

| 特性 | SceneManager 方案 | GameState 方案 |
|------|------------------|---------------|
| 层次 | GameState → SceneManager → Scene | GameState → Scene |
| 全局资源 | 需要传递或重复存储 | 直接在 GameState 中 |
| 代码量 | 更多抽象层 | 更少、更直接 |
| 理解难度 | 需要理解两层管理 | 只需理解一层 |
| 灵活性 | 可能过度设计 | 恰到好处 |

### 关键优势

1. **单一职责**：GameState 就是游戏的顶层状态
2. **资源共享**：网络、配置、资源都在一个地方
3. **简洁直观**：游戏状态 = 当前场景 + 全局资源
4. **易于扩展**：添加新场景只需实现 Scene trait

## 🚀 使用示例

### main.rs

```rust
#[macroquad::main(window_conf)]
async fn main() {
    // 创建游戏状态
    let mut game_state = GameState::new().await.expect("游戏初始化失败");
    
    println!("✅ 游戏启动成功");
    println!("📌 当前场景: {}", game_state.current_scene_name());
    
    // 游戏主循环
    loop {
        let dt = get_frame_time();
        
        // 更新
        game_state.update(dt)?;
        
        // 渲染
        game_state.render()?;
        
        // 处理场景切换
        game_state.process_scene_transition()?;
        
        next_frame().await;
    }
}
```

### 访问全局资源

```rust
// 在任何场景中都可以通过 GameState 访问全局资源
// （需要将 GameState 传递给 Scene，或使用其他方式）

// 方案1：Scene 持有 GameState 引用（Rust 中较复杂）
// 方案2：Scene 通过参数接收需要的资源
// 方案3：使用全局状态（如 Arc<Mutex>）（不推荐）

// 推荐：在 update 和 render 中传递必要的资源
trait Scene {
    fn update(&mut self, dt: f32, resources: &GameResources) -> GameResult<SceneTransition>;
}
```

## 📝 总结

GameState 作为场景管理器的设计：
- ✅ **更简洁**：减少一层抽象
- ✅ **更直观**：游戏状态就是场景 + 全局资源
- ✅ **更高效**：资源共享，避免重复
- ✅ **更易维护**：单一职责，清晰明了

这是一个**恰到好处**的设计，既不过度抽象，也不失灵活性。
