# macOS 窗口焦点问题说明

## 问题

在 macOS 上从 VS Code 启动 macroquad 程序时，窗口可能不会自动获取焦点。这是 macroquad 使用的 miniquad 库的已知限制。

## 原因分析

### ggez (使用 winit)
- ✅ winit 正确调用 Cocoa API 的 `makeKeyAndOrderFront`
- ✅ 窗口自动激活并获取焦点
- ✅ 从 VS Code 启动没有问题

### macroquad (使用 miniquad)
- ⚠️ miniquad 的窗口激活处理不够主动
- ⚠️ 特别是从其他应用启动时（如 VS Code）
- ⚠️ 窗口创建了但未激活，需要手动点击才能获取焦点

## 解决方案

### 方案 1：使用启动脚本（推荐）

使用提供的 `run.sh` 脚本：

```bash
./run.sh
```

或在 VS Code 中按 `Cmd+Shift+B` 选择"运行 Macroquad 地图查看器 (macOS 修复)"任务。

脚本使用 `open` 命令启动程序，这会确保窗口正确激活。

### 方案 2：手动使用 open 命令

```bash
# 先编译
cargo build --release

# 使用 open 命令启动
open target/release/client_macroquad
```

### 方案 3：从 Finder 启动

1. 编译程序：`cargo build --release`
2. 在 Finder 中找到 `target/release/client_macroquad`
3. 双击运行

### 方案 4：接受现状

直接 `cargo run --release`，窗口启动后手动点击一下即可。

## 为什么不修改代码？

macroquad 的窗口创建由 miniquad 处理，这是底层库的行为，无法通过简单的配置修改。可能的代码级解决方案需要：

1. **Fork miniquad**：修改 macOS 平台代码，添加 `makeKeyAndOrderFront` 调用
2. **使用 FFI**：直接调用 Cocoa API（但 macroquad 已经抽象了平台细节）
3. **切换到其他库**：如 winit（但这就失去了使用 macroquad 的意义）

这些方案都比较复杂，且不是 macroquad 的设计目标。macroquad 主要面向游戏开发，通常从 Finder 或独立启动，而不是从 IDE 启动。

## 推荐做法

开发时：
- 使用 `./run.sh` 或 VS Code 任务
- 或者接受手动点击窗口的小不便

发布时：
- 打包成 .app bundle
- 用户从 Finder 启动，没有焦点问题

## 对比 ggez

如果窗口激活是关键需求，可以考虑继续使用 ggez 版本（ClientRust）。ggez 在这方面表现更好，因为 winit 对 macOS 的支持更成熟。

macroquad 的优势在于：
- 更简单的 API
- 更好的跨平台支持（包括 Web/WASM）
- 更轻量级

选择哪个取决于项目优先级。
