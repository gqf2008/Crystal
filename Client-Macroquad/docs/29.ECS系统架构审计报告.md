## 2. 发现的问题

### 2.1 🔴 P0 — 系统优先级冲突（已修复）

**问题**: `ENTITY_RENDER` 和 `EFFECT_RENDER` 共享相同优先级 920。

**影响**: 实体渲染与特效渲染的执行顺序不确定，可能导致视觉闪烁或 Z-order 错误。

**涉及文件**:
- `Client-Macroquad/src/systems/mod.rs:133-134`

**修复**: 将 `EFFECT_RENDER` 优先级从 920 调整为 925，确保特效在实体之后渲染。

---

### 2.2 🔴 P0 — FloatingTextSystem 优先级错误（已修复）

**问题**: `FloatingTextSystem` 复用 `priority::PARTICLE` (610)，与 `ParticleSystem` 优先级冲突。

**影响**: 两个不同职责的系统共享同一优先级，执行顺序不可预测。

**涉及文件**:
- `Client-Macroquad/src/scenes/game_scene.rs:143-144`

**修复**:
1. 在 `priority` 模块新增 `FLOATING_TEXT = 615` 常量
2. 将 `FloatingTextSystem` 的注册改为使用 `priority::FLOATING_TEXT`

---

### 2.3 🔴 P0 — unsafe static mut 数据竞争（已修复）

**问题**: `map_viewer.rs` 使用 `static mut FIRST_RENDER: bool` + `unsafe` 块访问。

**影响**: 违反 Rust 安全保证，在多线程环境下可能触发未定义行为（UB）。

**涉及文件**:
- `Client-Macroquad/src/bin/map_viewer.rs:44, 701-705`

**修复**: 替换为 `AtomicBool` + `Ordering::Relaxed`，消除 unsafe。

---

### 2.4 🟠 P1 — Health.heal() 负数金额绕过防护（已修复）

**问题**: `heal()` 方法不校验 `amount` 参数，传入负数时会让 `current` 低于 0。

**影响**: 恶意或异常的网络包可能导致生命值变为负数，引发逻辑错误。

**涉及文件**:
- `Client-Macroquad/src/components/combat.rs:218-220`

**修复**:
- 添加 `amount <= 0` 提前返回守卫
- 使用 `saturating_add` 防止溢出

---

### 2.5 🟠 P1 — Mana.restore() 负数金额绕过防护（已修复）

**问题**: 与 Health.heal() 相同的缺陷。

**涉及文件**:
- `Client-Macroquad/src/components/combat.rs:251-253`

**修复**: 同上，添加负数守卫 + saturating_add。

---

### 2.6 🟠 P1 — Mana.consume() 缺少负数防护（已修复）

**问题**: `consume()` 不检查 `cost <= 0`，负数消耗会反向增加魔法值。

**涉及文件**:
- `Client-Macroquad/src/components/combat.rs:239-246`

**修复**: 添加 `cost <= 0` 提前返回 `false`。

---

### 2.7 🟡 P2 — 网络反序列化缺少范围校验

**问题**: `network_apply_system.rs` 中 `HealthChanged`/`ManaChanged` 处理直接用 `as i32` 转换，无范围校验。

**涉及文件**:
- `Client-Macroquad/src/systems/infra/network_apply_system.rs:1818-1870`

**风险**: 恶意服务端包可设置 `current > max` 或负数值。

**建议**: 在反序列化后添加 `current = current.clamp(0, max)` 校验。

---

### 2.8 🟡 P2 — Position 缺少 NaN/Infinity 校验

**问题**: `Position::new()` 和 `Position::from_grid()` 不检查 NaN 或 Infinity。

**涉及文件**:
- `Client-Macroquad/src/components/core.rs:22-39`

**风险**: NaN 坐标传播到渲染/物理系统，导致不可预测行为。

**建议**: 在 `from_grid()` 中添加 `debug_assert!(!x.is_nan() && !y.is_nan())`。

---

### 2.9 🟡 P2 — RefCell 嵌套借用风险

**问题**: 资源管理器使用 `Rc<RefCell<MLibrary>>`，嵌套 borrow_mut 会 panic。

**涉及文件**:
- `Client-Macroquad/src/resources/libraries.rs`

**风险**: 代码注释明确标注了此风险，但没有编译时保障。

**建议**: 添加运行时检测或重构为 `try_borrow_mut()` 模式。

---

### 2.10 🟡 P2 — 系统优先级无编译时唯一性检查

**问题**: 优先级常量手动维护，无机制检测重复值。

**涉及文件**:
- `Client-Macroquad/src/systems/mod.rs:49-149`

**风险**: 后续开发可能再次引入优先级冲突。

**建议**: 在 `SystemScheduler::add_system()` 中添加 `debug_assert!` 检查优先级唯一性，或在 CI 中添加静态分析。

---

### 2.11 🟡 P2 — RenderSystem 派生宏缺少 trait 实现验证

**问题**: `#[derive(RenderSystem)]` 只生成 `IntoSystemKind` 实现，不验证 `RenderSystem` trait 是否已实现。

**涉及文件**:
- `Client-Macroquad/ecs_macros/src/lib.rs`

**风险**: 开发者可能加 derive 但忘记实现 trait，导致运行时错误。

**建议**: 在宏生成的代码中添加 trait bound 约束。

---

### 2.12 🔵 P3 — sprite_system 备份文件残留

**问题**: `sprite_system/` 目录包含 `.bak3`, `.bak4`, `.bak6` 等备份文件。

**建议**: 清理备份文件，添加 `.gitignore` 规则。

---

### 2.13 🔵 P3 — 28+ TODO/FIXME 待实现项

**关键未实现功能**:
- `skill_system.rs`: 网络命令发送、冷却检查
- `pathfinding_system.rs`: PathFinder 实现
- `sound_system.rs`: 音效播放
- `entity_render_system.rs`: 精灵图数据加载

**建议**: 按模块逐步实现，不影响已有功能。

---

### 2.14 🔵 P3 — sprite_system 中 unwrap() 可能 panic

**问题**: `sprite_system.rs` 和 `character.rs` 中存在 3 处 `unwrap()` 调用。

**涉及文件**:
- `Client-Macroquad/src/systems/rendering/sprite_system.rs:37`
- `Client-Macroquad/src/systems/rendering/sprite_system/character.rs:~190`

**建议**: 改用 `unwrap_or_default()` 或 `?` 操作符。

## 3. 架构优点

1. **清晰的分层设计**: 5 层优先级体系（基础设施 → 输入网络 → 游戏逻辑 → 表现 → 渲染）职责分明。
2. **事件总线**: EventBus 提供类型安全、零拷贝的跨系统通信。
3. **工厂模式**: `GameWorld` 提供统一的实体创建接口，保证组件组合正确性。
4. **派生宏减少样板**: `#[derive(LogicSystem)]` / `#[derive(RenderSystem)]` 简化系统注册。
5. **服务端权威**: 战斗/生命值等核心状态由服务端控制，客户端仅做预测和展示。
6. **安全的实体查找**: `hecs` 对已销毁实体句柄返回 `Err`，不会 panic。
7. **统一坐标系统**: 网格坐标 (i32) 和浮点渲染坐标 (f32) 有清晰的转换路径。
