# Client-Macroquad 架构设计

**版本**: v0.1.0  
**创建日期**: 2025-11-12  
**目标**: 使用 macroquad 重新实现传奇2客户端，采用清晰的模块化架构

---

## 📚 设计原则

1. **模块化优先**: 每个模块职责单一，独立可测试
2. **参考但不复制**: 学习 ClientRust 的 ECS 架构，但适配 macroquad 特性
3. **渐进式开发**: 先建立骨架，再逐步填充功能
4. **保持简洁**: macroquad 的优势在于简单，不过度设计

### 2. ECS 模块 - 实体组件系统 ✅

**当前状态**: 使用 hecs，扁平化架构

**设计理念**: 
- ❌ 不使用 `ecs/` 嵌套目录（那是 ggez 迁移时的中间状态）
- ✅ 组件和系统直接放在顶层 `src/components/`, `src/systems/`
- ✅ GameWorld 直接放在 `src/game_world.rs`

**核心文件**:
```rust
// src/game_world.rs
pub struct GameWorld {
    pub world: hecs::World,
    pub start_time: Instant,
}

impl Deref for GameWorld {
    type Target = hecs::World;
    fn deref(&self) -> &Self::Target { &self.world }
}

// src/components/core.rs
pub struct Position { pub x: f32, pub y: f32 }
pub struct Velocity { pub dx: f32, pub dy: f32 }
pub struct Sprite { pub library: i32, pub index: i32, pub frame: i32 }
pub struct Dead; // 死亡标记

// src/systems/mod.rs
// TODO: 添加系统
// pub mod movement;
// pub mod render;
```

**使用示例**:
```rust
let mut world = GameWorld::new();

// 创建实体
let player = world.spawn((
    Position::new(100.0, 100.0),
    Velocity::zero(),
    Sprite::new(0, 100),
));

// 查询实体
for (id, (pos, vel)) in world.query::<(&mut Position, &Velocity)>().iter() {
    pos.x += vel.dx;
    pos.y += vel.dy;
}

// 清理死亡实体
world.cleanup_dead_entities();
```

## 🎯 与 ClientRust 的对比

| 特性 | ClientRust (ggez) | Client-Macroquad |
|------|------------------|------------------|
| **渲染引擎** | ggez (winit) | macroquad (miniquad) |
| **ECS** | hecs (完整) | 可选（简化） |
| **架构复杂度** | 高（五层系统） | 中（渐进式） |
| **平台支持** | 桌面 | 桌面 + Web |
| **开发难度** | 高 | 低 |
| **性能** | 高 | 高 |
| **代码量** | 50,000+ 行 | 目标 < 20,000 行 |

## 📝 编码规范

1. **模块组织**: 每个模块一个目录，包含 mod.rs
2. **命名约定**: 
   - 文件名: snake_case
   - 结构体: PascalCase
   - 函数: snake_case
3. **文档注释**: 所有 pub 项必须有文档
4. **错误处理**: 使用 Result 类型，不使用 unwrap
5. **异步**: macroquad 使用 async/await，保持一致
