一、服务端 ServerRust · 阻断级（8）

每一条在正式运营都是事故

阻断 1交易取消/断线/走路：已押物品永久销毁

位置actors/social.rs:3762-3779 / 3060-3062 / 1985-2065；触发源 world/session.rs:1494-1500

问题物品放入交易栏时已从背包移除只存在内存会话里；取消、任一方掉线、随便走一格（每次 Walk/Run 无条件发 TradeCancel）、确认时复检失败——四条路径全部直接丢会话，物品永久消失且会被存档持久化。

修复对齐 C# PlayerObject.TradeCancel：所有丢弃交易会话的路径统一归还双方物品（背包满转离线邮件）并通知对方关窗。

阻断 2交易金币不托管 + 扣减失败被吞 → 刷金

位置social.rs:3682-3705 / 2067-2136；player.rs:4893-4910

问题押金只校验不扣款（World 与 Social 不同 actor，锁定前去商店花光余额的窗口天然存在）；成交时扣款失败被 let _ = 吞掉，对方照常收金。AddGold 截顶仍返回 true，超额蒸发。

修复押金即时扣款托管（取消退回）；成交改「先扣验、任何一步失败整体中止退还」。

阻断 3商店出售不校验数量 → 1 件按 65535 件计价

位置actors/world/item.rs:3901-3926

问题扣物品按实际堆叠 min 截断，给钱却按客户端声明的 count，全程无上限校验。发包 SellItem(uid, 65535) 卖 1 件得 65535 倍金币。

修复按实际移除数量计价；加金失败回退物品。

阻断 4仓库满时存取吞物品

位置actors/inventory.rs:1027-1066

问题先从源格 take() 再查目标空位，容器满时提前返回，已取出的物品被 drop。仓库满存入、背包满取出都会永久丢件。

修复先查空位再 take，或失败分支放回原格。

阻断 5行会仓库取出越界 panic → 全服拒绝服务

位置social.rs:5578 / 5584 / 5612

问题客户端 u8 下标直接索引固定 100 格容器，取出分支三处裸索引无边界检查（C# 有）。一个 grid≥100 的包打挂 SocialActor，交易/组队/行会全瘫。

修复取出分支入口加 grid < storage_items.len() 校验。

阻断 6RangeAttack 长度检查 off-by-2 → 一个包全服掉线

位置gate/actor.rs:1878-1890

问题检查 len() < 19 但随后读 payload[17..21]（协议本身就需 21 字节）。19~20 字节载荷切片越界 panic，GateActor 死亡，全部会话中断。全 gate 逐函数对账后的唯一漏网。

修复改为 payload.len() < 21。

阻断 7硬编码 GM 口令，任何人自助提权

位置world/session.rs:2722-2736（const GM_PASSWORD = "C#Mir 4.0"）

问题C# 的公开默认值，且 Rust 版是编译期常量无法配置。任意新号聊天发这串口令即得 @GOLD/@MAKE/@LEVEL/@KILL 全部 GM 命令，无限速无审计。

修复GM 提权只认 DB admin_account 位，删自助口令；至少改 server.toml 配置 + 限速 + 审计日志。

阻断 8市场退款邮件被在线玩家下次存档整体抹除

位置world/market.rs:509 / 743；db/mod.rs:2749

问题被超价/拍卖过期的退款邮件无条件直写 DB；玩家在线时 ≤30 秒后自动存档按内存邮箱 DELETE 重写，退款邮件连同托管金蒸发。成交物品邮件路径有在线判断是对的，唯独两条退款路径漏了。

修复与成交邮件同构：在线走 AddMail，仅离线才 insert_mail。
